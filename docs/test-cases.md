# Тест-кейсы API

| Атрибут | Значение |
|---|---|
| Объект тестирования | Conduit (RealWorld) — платформа публикации статей |
| Уровень тестирования | API |
| Источник требований | [спецификация эндпоинтов RealWorld](https://realworld-docs.netlify.app/docs/specs/backend-specs/endpoints) |
| Окружение | `https://node-express-conduit.appspot.com/api` |
| Аутентификация | JWT, заголовок `Authorization: Token {jwt}` |
| Количество тест-кейсов | 13 |
| Тестировщик | Власенко Д. Р. |
| Дата составления | 18.09.2026 |

**Шкала приоритета:** Critical, High, Medium, Low.

**Общее предусловие для тест-кейсов с авторизацией:** зарегистрирован пользователь, получен действующий токен.

**Примечание о кодах ответа.** Публичные развёртывания Conduit возвращают разные коды для одной и той же ошибочной ситуации. В ожидаемых результатах негативных тест-кейсов указан допустимый набор кодов.

## 1. Аутентификация

### ТК-01. Регистрация нового пользователя с валидными данными

| Атрибут | Значение |
|---|---|
| Приоритет | Critical |
| Предусловия | Адрес электронной почты и имя пользователя не заняты |
| Шаги | 1. Отправить `POST /users` с телом, содержащим уникальные `email`, `username`, `password` |
| Ожидаемый результат | Код ответа 200 или 201. В теле ответа поле `user.email` равно переданному, `user.username` равен переданному, поле `user.token` не пустое |
| Автотест | `registersNewUser` |

### ТК-02. Регистрация с уже занятым адресом электронной почты

| Атрибут | Значение |
|---|---|
| Приоритет | High |
| Предусловия | Существует пользователь с известным адресом электронной почты |
| Шаги | 1. Отправить `POST /users` с адресом электронной почты существующего пользователя и новыми `username` и `password` |
| Ожидаемый результат | Код ответа 409 или 422. Тело ответа содержит непустой объект `errors`. Новый пользователь не создан |
| Автотест | `rejectsRegistrationWithTakenEmail` |

### ТК-03. Вход с корректными учётными данными

| Атрибут | Значение |
|---|---|
| Приоритет | Critical |
| Предусловия | Пользователь зарегистрирован, его адрес электронной почты и пароль известны |
| Шаги | 1. Отправить `POST /users/login` с корректными адресом электронной почты и паролем<br>2. Отправить `GET /user` с полученным токеном в заголовке `Authorization` |
| Ожидаемый результат | Шаг 1: код ответа 200, поле `user.token` не пустое, длина токена не менее 10 символов.<br>Шаг 2: код ответа 200, поле `user.username` равно имени вошедшего пользователя |
| Автотест | `logsInWithValidCredentials` |

### ТК-04. Вход с неверным паролем

| Атрибут | Значение |
|---|---|
| Приоритет | Critical |
| Предусловия | Пользователь зарегистрирован |
| Шаги | 1. Отправить `POST /users/login` с корректным адресом электронной почты и заведомо неверным паролем |
| Ожидаемый результат | Код ответа 401, 403 или 422. Тело ответа содержит непустой объект `errors`. Токен не выдан |
| Автотест | `rejectsLoginWithInvalidCredentials` |

### ТК-05. Вход с незарегистрированным адресом электронной почты

| Атрибут | Значение |
|---|---|
| Приоритет | High |
| Предусловия | Адрес электронной почты не зарегистрирован в системе |
| Шаги | 1. Отправить `POST /users/login` с незарегистрированным адресом электронной почты и произвольным паролем |
| Ожидаемый результат | Код ответа 401, 403 или 422. Токен не выдан |
| Автотест | `rejectsLoginWithUnknownEmail` |

## 2. Статьи

### ТК-06. Создание статьи авторизованным пользователем

| Атрибут | Значение |
|---|---|
| Приоритет | Critical |
| Предусловия | Получен действующий токен |
| Шаги | 1. Отправить `POST /articles` с токеном в заголовке `Authorization` и телом, содержащим `title`, `description`, `body` |
| Ожидаемый результат | Код ответа 200 или 201. Поле `article.slug` не пустое, `article.title` и `article.body` равны переданным, `article.author.username` равен имени пользователя, от чьего токена выполнен запрос |
| Постусловия | Созданную статью удалить |
| Автотест | `createsArticleAsAuthorizedUser` |

### ТК-07. Создание статьи без авторизации

| Атрибут | Значение |
|---|---|
| Приоритет | Critical |
| Предусловия | Отсутствуют |
| Шаги | 1. Отправить `POST /articles` без заголовка `Authorization` с корректным телом статьи |
| Ожидаемый результат | Код ответа 401, 403 или 422. Статья не создана |
| Автотест | `rejectsArticleCreationWithoutAuthorization` |

### ТК-08. Чтение опубликованной статьи анонимным пользователем

| Атрибут | Значение |
|---|---|
| Приоритет | High |
| Предусловия | Создана статья, её `slug` известен |
| Шаги | 1. Отправить `GET /articles/{slug}` без заголовка `Authorization` |
| Ожидаемый результат | Код ответа 200. Поля `article.slug` и `article.title` равны значениям созданной статьи |
| Постусловия | Статью удалить |
| Автотест | `readsArticleAsAnonymousUser` |

### ТК-09. Удаление собственной статьи автором

| Атрибут | Значение |
|---|---|
| Приоритет | High |
| Предусловия | Пользователь создал статью, её `slug` известен |
| Шаги | 1. Отправить `DELETE /articles/{slug}` с токеном автора<br>2. Отправить `GET /articles/{slug}` |
| Ожидаемый результат | Шаг 1: статья удалена.<br>Шаг 2: код ответа 404 или 422 — статья недоступна |
| Автотест | `deletesOwnArticle` |

### ТК-10. Удаление чужой статьи

| Атрибут | Значение |
|---|---|
| Приоритет | Critical |
| Предусловия | Пользователь А создал статью. Зарегистрирован пользователь Б, получен его токен |
| Шаги | 1. Отправить `DELETE /articles/{slug}` с токеном пользователя Б<br>2. Отправить `GET /articles/{slug}` |
| Ожидаемый результат | Шаг 1: код ответа 401 или 403 — в удалении отказано.<br>Шаг 2: код ответа 200 — статья пользователя А осталась доступна |
| Постусловия | Статью удалить от имени пользователя А |
| Автотест | `rejectsDeletionOfForeignArticle` |

## 3. Комментарии

### ТК-11. Создание комментария авторизованным пользователем

| Атрибут | Значение |
|---|---|
| Приоритет | High |
| Предусловия | Создана статья, получен действующий токен |
| Шаги | 1. Отправить `POST /articles/{slug}/comments` с токеном и телом комментария |
| Ожидаемый результат | Поле `comment.id` не пустое, `comment.body` равен переданному, `comment.author.username` равен имени пользователя, от чьего токена выполнен запрос |
| Постусловия | Статью удалить |
| Автотест | `createsComment` |

### ТК-12. Чтение комментариев анонимным пользователем

| Атрибут | Значение |
|---|---|
| Приоритет | Medium |
| Предусловия | Создана статья, к ней добавлен комментарий, его идентификатор известен |
| Шаги | 1. Отправить `GET /articles/{slug}/comments` без заголовка `Authorization` |
| Ожидаемый результат | Список комментариев содержит комментарий с известным идентификатором |
| Постусловия | Статью удалить |
| Автотест | `readsCommentsAsAnonymousUser` |

### ТК-13. Создание комментария без авторизации

| Атрибут | Значение |
|---|---|
| Приоритет | Critical |
| Предусловия | Создана статья |
| Шаги | 1. Отправить `POST /articles/{slug}/comments` без заголовка `Authorization` с корректным телом комментария |
| Ожидаемый результат | Код ответа 401, 403 или 422. Комментарий не создан |
| Постусловия | Статью удалить |
| Автотест | `rejectsCommentWithoutAuthorization` |
